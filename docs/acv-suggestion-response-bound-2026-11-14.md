# Air Canada Vacations suggestion RPC response bound — 2026-11-14

The widget-mediated `GET /geo-insight/suggestions` response is a structured location endpoint used by the package-location picker. `lookupVacationSuggestions` previously passed the browser response directly to `response.json()`, so a malformed or unexpectedly large provider response could consume unbounded application memory before the existing 20-option display cap was applied.

Added `readVacationSuggestionResponse`, which rejects an advertised `Content-Length` above 1,000,000 bytes, rejects a decoded response body above the same limit, parses JSON only after the size check, and reports malformed/missing bodies as invalid provider responses. The existing exact-term validation and 20-item suggestion cap still run after parsing. The adapter remains inside the ordinary ACV widget session and does not extract, persist, or replay its Authorization header. This is an application-side parse/memory bound; Playwright may buffer the browser response before `response.body()` returns it.

Repeated exact autocomplete queries now use a process-local cache with a five-minute TTL and a maximum of 100 entries. The cache key includes lookup kind, case-normalized exact term, and (for destinations) selected origin code and label. Cache hits retain the original `observedAt` and expose `cached: true` plus `cacheExpiresAt`; they do not refresh the observation timestamp or contact ACV. Only successful, validated provider responses are cached. This is location metadata, not fare or availability inventory, and the cache is not shared between app processes.

Focused verification: `node --test tests/vacation-suggestions.test.mjs tests/vacation-search.test.mjs` passed **28/28**; the suggestion suite alone passed 10/10 including the cache-eviction regression. Final-tree verification: `npm test` passed **619/619** (89.6s); `npm run build` passed after the implementation changes; `npm audit --audit-level=low` found **0 vulnerabilities** after the implementation changes.

No live provider request was made for this change. Direct unauthenticated ACV suggestions access previously returned HTTP 401; no approved server-token contract has been established. The package search still uses the ordinary widget flow and its page responses do not yet have a uniform byte cap. This change does not close reverse-endpoint source authorization, rate-policy, live drift, or package-RPC gaps.
