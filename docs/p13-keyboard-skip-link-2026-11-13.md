# P13 keyboard skip link — 2026-11-13

Added a keyboard-first link before the page header that moves focus directly to the Flight Search section. The destination is programmatically focusable and visibly outlined on focus; the link itself becomes visible when focused and has high-contrast dark/light styles.

Verification used the isolated local production build `.next-accessibility-skip-build` on loopback. `check:accessible-controls` confirmed the skip link is the first keyboard focus target, Enter moves focus to the unique Flight Search destination, 112 controls have accessible names, there are no duplicate IDs or broken ARIA references, all eight fieldsets have legends, dynamic airline suggestions are politely announced and keyboard-operable with exposed pressed state; 85 visible Tab targets were traversed in rendered order, accounting for Chromium’s internal date-input Tab steps; and there are no browser errors. `check:responsive-ui` reported no horizontal overflow at 320, 375 or 768 CSS pixels, with provider traffic blocked. `check:theme-contrast` sampled 162 visible texts in both themes and found no failures (minimum 5.27:1 dark / 5.53:1 light). `npm test` passed 550/550; `npm run build` passed; `npm audit --audit-level=low` found zero vulnerabilities.

The 320 CSS-pixel check is a 400%-equivalent reflow width from a 1280 CSS-pixel baseline, not a browser zoom conformance test. Screen-reader output, keyboard traversal through other dynamic states, reduced-motion behavior, touch-target review, high-contrast modes, and physical devices remain open. This is targeted smoke evidence, not a WCAG conformance claim. No live travel-provider request ran.
